# 密钥与配置管理

> 原则一句话：**仓库里只有模板，真值永远在本机的 `.env`**。
> 本文写清三件事：哪些文件不入库、提交前怎么自检、万一泄露了怎么收场。

## 一、什么进仓库，什么不进

| 类型 | 处理方式 | 具体文件 |
|------|----------|----------|
| 环境变量模板 | **入库** | `.env.example` |
| 真实环境变量 | 不入库 | `.env`、`.env.local`、`.env.*.local` |
| 私钥 / 证书 | 不入库 | `*.pem`、`*.key`、`*.p12`、`secrets/` |
| 数据库与备份 | 不入库 | `*.db`、`*.sqlite*`、`data/*.bak-*` |
| 上传文件、日志、运行期产物 | 不入库 | `uploads/`、`logs/`、`scripts/logs/`、`scripts/.run/` |
| 本地 Agent 记忆与笔记 | 不入库 | `.workbuddy/`、`.codex/`、`.agents/` |
| 含服务器凭据的运维脚本 | 不入库 | `scripts/ssh_*.py`、`scripts/sftp_put.py`、`scripts/deploy_push.py` |
| 大体积二进制（计划书等） | 不入库，按需发 Release | 根目录 `*.docx`、`*.zip`、`*.whl` |
| 个人学习脚本 | 不入库，本地保留 | `ai/agents/react_loop.py` |

对应规则全部写在 `.gitignore`，容器构建另有一份 `.dockerignore`（不把 `.env`、`.git`、文档打进镜像）。

## 二、提交前自检

```bash
python scripts/check_secrets.py           # 扫全部已跟踪文件
python scripts/check_secrets.py --staged  # 只扫暂存区（pre-commit 用）
```

检查三类东西，命中即退出码 1：

1. **密钥形态**：`sk-` 长串、GitHub token、AWS Access Key、Slack token、私钥块、疑似硬编码口令。
2. **基础设施**：私网 IPv4（`192.168.*`、`10.*`、`172.16–31.*`）及带端口的地址。
3. **个人信息**：`C:\Users\<用户名>` 这类绝对路径（会暴露本机账号名）。

三条使用约定：

- 输出**不打印完整命中内容**，只留前 4 个字符 + 长度，避免「查泄漏的日志本身变成泄漏源」。
- 模板文件里的占位符（`change-me`、`your-`、`example.com`、`127.0.0.1`）直接放行，
  否则告警会被误报淹没，最后没人看。
- Docker 默认网关 `172.19.0.1` 属环境约定，已加入白名单。

想在提交阶段自动拦截，可在本地装一个钩子（钩子不进版本库，属个人环境）：

```bash
printf '#!/bin/sh\npython scripts/check_secrets.py --staged || exit 1\n' > .git/hooks/pre-commit
chmod +x .git/hooks/pre-commit
```

## 三、密钥怎么配

1. `cp .env.example .env`
2. 只填本机需要的那几项。常见最小集：
   - 演示模式：什么都不用填（`DB_BACKEND=sqlite`、`AI_ENABLED=false`）
   - 接真实模型：`OPENAI_API_KEY` + `OPENAI_BASE_URL`（带 `/v1`）+ `OPENAI_MODEL`
   - 接 MySQL：`DB_BACKEND=mysql` + `DB_*`
3. 换机器只带 `.env`，不要带进仓库；`.env` 里改完立刻生效，不需要改代码。

生产环境不要用 `.env` 分发密钥，改用部署平台的密钥管理（环境变量注入 / 密管服务）。
`JWT_SECRET` 必须换成随机长串，演示口令 `Demo@12345` 必须作废。

## 四、万一已经泄露了

按顺序做，不要跳步：

1. **先轮换密钥**（在网关/云控制台作废旧 key、发新 key）。只要 key 进过任何一次提交，
   就当作已泄露 —— 历史可以被克隆、被缓存、被 fork，删文件不等于收回。
2. **再清仓库**：
   - 只影响当前版本：改文件 + 提交即可；
   - 影响历史：需要重写历史（`git filter-repo --invert-paths` 或 `--replace-text`），
     然后强推，并删除所有旧分支与标签。
3. **最后清远端残留**：强推后旧对象在 GitHub 上可能仍可按 SHA 直达。
   彻底清除有两条路：删除仓库重建，或联系 GitHub Support 请求清理不可达对象。
   fork 是独立副本，必须单独处理。

> 本仓库在 2026-10-17 上线时执行过两轮历史重写：第一轮剥离本地笔记目录与二进制大文件，
> 第二轮替换本机绝对路径与公网 IP。旧历史副本保留在作者本机的 bundle 备份里，不入库。

## 五、接口不下发本机路径

`source_ref` / `storage_path` / `file_paths` 是**服务端句柄**（后端靠它重新定位文件），
历史数据里什么形态都有：相对对象键（`data/samples/lab.jpg`）、上传目录相对路径
（`uploads/2026/10/09/ab12cd.jpg`），甚至整条本机绝对路径（`C:/Users/<用户名>/...`）。

原样放进响应的代价：用户名、盘符、部署目录会进页面，再跟着进**截图、浏览器缓存和工单**。
一张贴到 README 的界面图就能把它带出去。

**规则：响应只给文件名，路径留在服务端。**

```python
from app.utils.display import public_file_name, public_file_names

source_name = public_file_name(task.source_ref)          # → "lab.jpg"
attachments = public_file_names(submission.file_paths)   # → "作业1.pdf、作业2.pdf"
```

- 前端只读 `sourceName`，**不要再读 `sourceRef` / `source_ref`**；
- 需要下载或预览走 `file_id`（`/api/files/{id}/preview`），不要用路径；
- 新增「返回文件信息」的接口，先过 `app/utils/display.py` 再出参；
- 已按此改造：`/api/review/scan/tasks`（拍照批改的「素材」列）、`/api/vision/tasks`、
  作业附件与提交文件、学情接口里的 `filePaths`。

> 边界说明：库里存的仍是原始句柄（推理与下载要用），**只改出口不改存储**，
> 因此不需要数据回填，历史记录也不会再显示路径。

## 六、相关文件

- `.gitignore` / `.dockerignore`：忽略规则
- `.env.example`：全部可用配置项与默认值
- `scripts/check_secrets.py`：本文第二节的自检脚本
- `app/utils/display.py`：本文第五节的脱敏入口（路径 → 文件名）
- `app/config.py`：配置字段的唯一来源（新增配置项先改这里，再同步模板）

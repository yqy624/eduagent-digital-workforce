## 一、现状一览

| 能力 | 当前实现 | 是否占位 | 覆盖的用途 |
|---|---|---|---|
| `vision` | `placeholder` | ✅ 占位 | 课堂行为 / 实验室安全 / 考试监考 / 拍照批改 |
| `vision` | `yolo-platform` | ❌ 真实 | 已落地 YOLO11n（GPU），**但默认不启用** |
| `llm` | `placeholder` | ✅ 占位 | 解题讲解 / 评语生成 / 知识问答 / 学情报告 / 适龄改写 |
| `embedding` | `placeholder` | ✅ 占位 | 文本向量化（RAG 检索侧） |

**一句话**：占位实现不是随机假数据，而是**确定性**的结构化结果——同一输入永远产出同一输出，业务流程、前端渲染、回归测试都可复现。

已实测：

```

edu-ai-platform: torch 2.13.0+cpu  · cuda=False  ← 因此视觉走子进程转发，不在本进程装 torch
```

## 二、统一契约（所有模型共用）

所有调用都返回 `ModelResult[T]`，**不允许抛异常给业务层**：

```python
ModelResult(
    ok: bool,
    data: T | None,
    meta: ModelMeta(
        provider, model_name, model_version, capability,
        is_placeholder, status, latency_ms, attempts, request_id, error
    ),
    error: ModelError(kind, message, detail, retryable) | None
)
```

错误分类 `ErrorKind`：`invalid_input` / `not_configured` / `timeout` / `provider_error` / `rate_limited` / `unsupported` / `circuit_open`。
其中 `timeout`、`provider_error`、`rate_limited` 会自动重试（指数退避，默认 3 次），连续失败 5 次触发熔断。

## 三、占位模型逐项清单

### 3.1 视觉识别（capability = `vision`）

**实现位置**：`app/core/models/placeholders/vision.py`

**输入** `VisionRequest`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `scene` | enum | `classroom` / `lab_safety` / `exam_proctor` / `paper_grading` |
| `source_ref` | str | 图片/视频路径或已上传文件 id |
| `source_type` | enum | `image` / `video` / `stream` |
| `conf` / `iou` / `imgsz` | float/int | 推理参数，默认 0.25 / 0.45 / 640 |
| `with_identity` | bool | 是否做身份映射，默认 True |

**输出** `SceneState`：

```json
{
  "scene": "classroom",
  "source_ref": "...",
  "objects": [{"cls_name":"person","conf":0.87,"bbox":[x1,y1,x2,y2],"seat_ref":"R1-C1"}],
  "events":  [{"type":"head_down","severity":"warning","confidence":0.8,
               "duration_s":96.2,"subject_ref":"S2024001","evidence":{"seat":"R1-C1"}}],
  "summary": {"object_count":3,"event_count":2,"classes_seen":{...},"is_placeholder":true}
}
```

**各场景占位剧本**：

| 场景 | 产出类别 | 产出事件 |
|---|---|---|
| `classroom` | person / book / cell phone | `head_down`(warning) · `phone_detected`(warning) · `attention_drop`(info) |
| `lab_safety` | person / gloves / goggles / lab_coat | `no_gloves`(critical) · `no_goggles`(critical) · `no_lab_coat`(warning) |
| `exam_proctor` | person / cell phone / book | `phone_detected`(critical) · `head_turn`(warning) · `leave_seat`(warning) |
| `paper_grading` | question_block / handwriting | `block_located`(info) · `low_confidence`(warning) |

**替换步骤**：

1. 在 `app/core/models/adapters/` 下新增一个类，继承 `VisionProvider`，只实现 `_acall()`：
   ```python
   class MyVisionProvider(VisionProvider):
       name = "my-yolo"
       is_placeholder = False
       async def _acall(self, request: VisionRequest) -> SceneState: ...
   ```
2. 在 `app/core/models/registry.py` 的 `_bootstrap()` 里注册：
   `registry.register(MyVisionProvider(), capability="vision")`
3. 改环境变量 `MODEL_VISION_BACKEND=my-yolo`（或 `registry.set_default("vision","my-yolo")`）
4. 跑 `python scripts/smoke_models.py --vision-backend my-yolo` 验收

> **已备好的真实实现**：`adapters/yolo_platform.py` 通过子进程调用 `yolo-platform/scripts/bridge_infer.py`。
> 启用方式：`MODEL_VISION_BACKEND=yolo-platform`（需 `yolo-platform` 目录存在且权重已下载）。
> **注意**：它只产出检测框，不产出语义事件（事件属于 edu 侧推理层，保持分层）。

### 3.2 大模型（capability = `llm`）

**实现位置**：`app/core/models/placeholders/llm.py`

**输入** `LLMRequest`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `task` | enum | 见下表五类任务 |
| `messages` | list[LLMMessage] | `{role: system|user|assistant, content}` |
| `prompt` | str | 便捷入口，会转成一条 user 消息 |
| `temperature` / `max_tokens` | float/int | 默认 0.3 / 1024 |
| `context` | dict | 透传给实现（如检索到的片段） |

**输出** `LLMResultData`：`{text, finish_reason, usage:{prompt_tokens, completion_tokens, total_tokens}}`

| 任务 | 用途 | 真实模型建议 |
|---|---|---|
| `solve_explain` | 解题讲解、分步骤推导 | Qwen3-8B / 教育微调版 |
| `comment_generate` | 教师评语生成 | Qwen3-4B 足够 |
| `rag_answer` | 基于本地知识库的问答 | Qwen3-8B + RAG |
| `insight_report` | 学情分析报告生成 | Qwen3-8B |
| `age_adapt` | 适龄表达改写 | Qwen3-4B |

**替换步骤**：同上，继承 `LLMProvider`，注册到 `capability="llm"`，改 `MODEL_LLM_BACKEND`。

**本机约束（实测）**：RTX 4060 Laptop **8GB 显存**，可用显存约 7542 MiB。
Qwen3-4B（Q4）约 3GB 轻松；Qwen3-8B 约 5.5GB 是上限；**14B 及以上跑不了**。
另外 qwen3 默认开启 thinking，会吃掉约 2/3 的 token 预算——评测时务必固定 `<arg_key:6124c78e>`，否则答案被截断会被误判成"能力不足"。

### 3.3 向量化（capability = `embedding`）

**实现位置**：`app/core/models/placeholders/embedding.py`

**输入** `EmbeddingRequest`：`{texts: list[str], normalize: bool}`
**输出** `EmbeddingResultData`：`{vectors: list[list[float]], dim: int, model_name: str}`

占位实现用的是**字符二元组哈希向量**（dim=384），不是随机数——字面相近的文本相似度更高，RAG 检索演示才有意义。
注意内部用 `hashlib` 而非 Python 内置 `hash()`（后者按进程随机加盐，跨进程结果不可复现）。

**替换步骤**：继承 `EmbeddingProvider`，注册到 `capability="embedding"`，改 `MODEL_EMBEDDING_BACKEND`。
真实模型建议 `bge-m3`（ollama 里已经有一份，但那是 edu 侧环境；若要在 yolo-platform 用需重新拉）。

## 四、替换的通用验收

```bash
# 1) 契约层冒烟（三类能力 + 确定性校验）
python scripts/smoke_models.py --vision-backend <你的实现名>

# 2) 端到端（登录 -> 建任务 -> 查事件 -> 概览）
DB_BACKEND=sqlite python scripts/seed_demo.py
DB_BACKEND=sqlite python scripts/smoke_app.py

# 3) 看运行时到底跑的是谁
curl -H "Authorization: Bearer <token>" http://localhost:8001/api/vision/models
```

验收标准只有两条：

1. `smoke_models.py` 里 **不出现** "回落到占位实现" 的告警；
2. `meta.is_placeholder` 为 `False`，且 `/api/vision/overview` 的 `placeholdersInUse` 里不再包含该能力。

## 五、前置条件与许可协议

| 模型 | 权重来源 | 许可 | 显存/依赖 | 私有化 |
|---|---|---|---|---|
| YOLO11n/s/m | hf-mirror.com/Ultralytics/YOLO11 | **AGPL-3.0** | 0.11 GB（n，实测） | ✅ 本地 |
| Qwen3-4B/8B | ollama / HF / ModelScope | Apache-2.0（Qwen 系列） | 3 / 5.5 GB（Q4） | ✅ 本地 |
| bge-m3 | ollama `bge-m3` | Apache-2.0 | ~1.2 GB | ✅ 本地 |
| 商用 API（OpenAI / DashScope / Anthropic） | 云端 | 各家服务条款 | 无 | ❌ |

> **AGPL-3.0 提醒**：Ultralytics YOLO 的 AGPL 许可对"通过网络提供服务"有传染性要求。
> 若用于商业闭源交付，需购买商业许可或改用 Apache/MIT 许可的实现。毕业设计场景无影响，
> 但写在论文与简历里时应主动注明，这是个加分项而非减分项。

**网络提示（实测）**：GitHub Releases 在本机不可达（curl 28 超时），权重请走 `hf-mirror.com`；
PyTorch 官方源约 0.1 MB/s，改用 `https://mirror.sjtu.edu.cn/pytorch-wheels/cu124/` 约 2.16 MB/s。
sjtu 的 cu124 目录最高只到 torch **2.6.0**（2.7.0+ 全部 404），配套 torchvision 为 **0.21.0**。

## 0. 结论：最短启动路径

```bash
cd ~/Desktop/edu-ai-platform

# ① 准备数据（首次或库被删后执行一次）
DB_BACKEND=sqlite .venv/Scripts/python.exe scripts/seed_demo.py

# ② 启动服务
DB_BACKEND=sqlite .venv/Scripts/python.exe run.py --host 127.0.0.1 --port 18010

# ③ 打开浏览器
#    http://127.0.0.1:18010/platform      ← 新平台主页（六大模块）
#    http://127.0.0.1:18010/              ← 数字员工协作台（默认入口）
```

**唯一容易踩的坑**：`DB_BACKEND` 默认是 `mysql`，`.env` 里没写这一项。
本地没起 MySQL 就必须显式传 `DB_BACKEND=sqlite`，否则启动后所有数据库操作失败。

## 6. 一键启动（推荐 · 含全部依赖）

> **三项目整合后**：全套编排已收口到
> `D:\Windows\soft\pycharm\PyCharm2023.2.5\workspace_ai-suite\scripts\start_all.ps1`
> （多起一个业务 B · 协同文档，并负责三项目端口分配）。
> 下面这个 edu 自带的脚本仍然可用，只起 A 侧 6 个服务。

```powershell
cd ~\Desktop\edu-ai-platform
powershell -ExecutionPolicy Bypass -File .\scripts\start_all.ps1
```

按依赖顺序拉起 6 个服务，并在终端**持续输出**服务名 / 地址 / 端口 / PID / 实时日志：

| # | 服务 | 端口 | 地址 |
|---|---|---|---|
| 1 | Milvus 向量库（Docker，只检测） | 19530 | http://127.0.0.1:19530 |
| 2 | MinIO 对象存储 | 9000 | http://127.0.0.1:9000（控制台 9001） |
| 3 | Elasticsearch 7.6.2 | 9200 | http://127.0.0.1:9200 |
| 4 | rag-go 检索服务 | 18000 | http://127.0.0.1:18000 |
| 5 | yolo-platform 视觉服务 | 18030 | http://127.0.0.1:18030 |
| 6 | edu-ai-platform 主服务 | 18010 | http://127.0.0.1:18010 |

启动后脚本每 15 秒打印一次心跳（在线 / 端口 / HTTP 状态），并实时跟随各服务日志（带 `[edu]`、`[rag]` 等前缀）。

**参数**

| 参数 | 作用 |
|---|---|
| `-Stop` | 停止**由本脚本启动过**的服务（含上一轮启动、本次被“接管”的；读 `scripts\.run\pids.json` 中 `owned=true` 的项） |
| `-StopAll` | 停止 `pids.json` 里记录的**全部**服务，含纯外部复用实例 |
| `-Restart` | 先 `-Stop` 再启动（重启我这一套）；与 `-StopAll` 合用则先全停再启动 |
| `-Only "yolo,edu"` | 只启动部分服务（短名 `milvus,minio,es,rag,yolo,edu`） |
| `-NoTail` | 只输出心跳状态，不跟随日志 |
| `-ReadyTimeout 120` | 调整等待端口就绪的默认秒数 |

**停止分三级**（安全边界清晰）

| 操作 | 停止范围 |
|---|---|
| `Ctrl+C` | 只停**本次脚本自启**的服务（绝不误杀复用 / 接管实例） |
| `-Stop` | 停**由脚本启动过**的服务（含上一轮脚本启动、本次被“接管”的） |
| `-StopAll` | 停 `pids.json` 记录的全部（含纯外部复用实例） |

**服务已经在跑时怎么办**（实测验证）

- **身份校验**：端口被占用时，脚本会请求该服务的健康接口，校验返回里是否含本项目身份关键词（edu→`EduAgent`、rag→`rag_ready`、yolo→`yolo-platform`、es→`cluster_name`、minio→响应头 `Server: MinIO`）。命中才复用；命中不了就报 **`端口冲突`** 并跳过（既不接管也不启动），避免把别人的进程当成自己的服务。
- **接管 vs 复用**：端口上的实例若正是上一轮脚本启动的（PID 与 `pids.json` 一致且 `owned=true`），标记为 **`接管`**；否则标记为 **`复用`**。两种情况都会进入持续输出循环，不再直接退出。
- **PID 以端口反查为准**：不再信任 `Start-Process` 返回的 PID（它常是 shim —— ES 的 `cmd.exe`、venv 的 python 启动器），改用 `Get-NetTCPConnection -LocalPort N -State Listen` 反查**真实监听 PID**，同时记下 shimPid 以便 `/T` 杀掉整棵进程树。
- **pids.json 合并语义**：记录 `{pid, shimPid, owned, port, startedAt}`，读写为“读旧 + 合并 + 丢弃已死进程”，绝不会再被覆盖成 `{}`；旧版扁平格式会自动升级为 v2。
- Milvus 是 Docker 容器，脚本**只检测不代管**（绝不 `taskkill`，否则会误杀 WSL 转发的 `wslrelay`）。
- 每个服务的输出同时落盘到 `scripts\logs\<key>.out.log` / `<key>.err.log`。
- 本机存在 `http_proxy`/`HTTP_PROXY` 这类仅大小写不同的重复环境变量，会让 `Start-Process` 直接报错，脚本已在本进程作用域内清空。

**实测（2026-10-09）**：冷启动 6/6 就绪（ES ~35s、MinIO ~7s、rag-go ~3s、yolo ~3s、edu ~6s）；随后逐项验证通过 —— 「服务已在跑」时的复用与接管（含 shimPid 继承）、身份校验拦截伪装服务（主服务端口被别的 python 占用时报端口冲突）、`-Stop` / `-StopAll` 的停止范围、pids.json 的 v1→v2 迁移与合并语义。

## 8. 排错速查

| 现象 | 原因 / 处理 |
|---|---|
| `缺少依赖 'uvicorn'` | 用了系统 python，改用 `.venv/Scripts/python.exe` |
| 数据库连不上 / 报 mysql 错 | 漏了 `DB_BACKEND=sqlite` |
| `NOT NULL constraint failed: id` | SQLite 下 BigInteger 主键问题，已在 `app/database.py` 用 `@compiles` 修掉；若复现检查是否被覆盖 |
| 登录 401 | body 没带 `role`，或没跑 `seed_demo.py` |
| 端口占用 | 换 `--port`，或 `netstat -ano \| findstr 18010` 找占用进程 |
| 读返回字段取不到 | 中间件只把**响应**转 camelCase，请求体必须 snake_case（如 `source_ref`，返回是 `sourceRef`） |

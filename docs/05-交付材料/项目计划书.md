# EduAgent 项目计划书

## 一、项目基本信息

项目名称：EduAgent — 基于多 Agent 的智慧教育学习运营平台

项目类型：人工智能应用、教育数字化、智慧教学平台、学习分析系统

参赛方向建议：AI+教育、数字化校园、软件创新应用、互联网+创新创业、生成式 AI 行业应用

项目阶段：Preview / MVP，已具备可演示原型和核心业务闭环

目标场景：高校课程教学、职业教育实训课程、培训机构课程运营、AI 教育应用试点

## 二、项目摘要

EduAgent 是一个面向学校和培训机构的 AI 教育平台，围绕管理员、教师、学生三类角色构建完整的教学运营闭环。平台覆盖课程管理、选课管理、作业发布、作业提交、匿名互评、教师评分、成绩分析、活动通知、资料上传、课程知识库、RAG 问答、学情诊断、学习计划生成和 AI 辅助批改等功能。

项目的核心创新在于将多 Agent 工作流嵌入真实教学业务流程。AI 不再只是一个独立聊天窗口，而是能够读取课程资料、作业记录、提交内容、成绩数据和互评信息，并通过工具调用生成可解释、可追踪、可由教师审核的教学建议。平台以 Human-in-the-loop 为原则，教师保留最终评分权和教学决策权，AI 主要承担辅助分析、建议生成、资料检索和效率提升的角色。

本项目适合用于教育数字化改革试点和参赛展示，具备明确痛点、可运行系统、技术可行性、应用价值和持续迭代空间。

## 三、项目背景与问题分析

### 1. 行业背景

教育信息化平台已经在高校和培训机构中广泛应用，但大量系统仍停留在“管理流程线上化”阶段。课程、作业、成绩、资料和反馈虽然被记录下来，却很少被进一步用于个性化学习支持、教学质量改进和智能决策。

与此同时，大语言模型和智能 Agent 技术正在快速进入教育领域。它们具备自然语言理解、知识解释、内容生成和任务规划能力，但如果缺少课程资料、作业表现和教师审核机制，AI 容易变成脱离课堂的通用问答工具。

EduAgent 正是在这一背景下提出：让 AI 进入教育平台内部，基于真实教学数据提供可信、可控、可追踪的智能服务。

### 2. 用户痛点

#### 教师痛点

- 作业批改任务重，反馈撰写耗时。
- 学生问题重复度高，课程资料答疑占用大量精力。
- 班级学情掌握滞后，往往等到考试或期末才暴露问题。
- 现有数据平台多提供统计图表，缺少具体教学建议。
- 使用通用 AI 工具批改或答疑时，无法自然关联课程资料和作业要求。

#### 学生痛点

- 不知道自己的薄弱点在哪里。
- 面对课程资料和作业要求时，缺少个性化学习路径。
- 提问时常得到泛泛回答，缺少课程上下文。
- 作业反馈周期较长，难以及时调整学习策略。
- 缺少高质量同伴互评和反思机制。

#### 管理员痛点

- 平台运营数据分散，课程、用户、活动、任务状态难以统一查看。
- 缺少课程运行异常、作业积压和教学参与情况的直观入口。
- 教育数字化成果展示需要真实系统支撑，而非单一概念方案。

### 3. 机会判断

AI 教育应用的关键不在于简单接入模型，而在于将模型能力和教育业务数据深度结合。EduAgent 以课程、作业、成绩、资料为核心数据底座，以 RAG 和 Agent 工作流为智能层，以教师审核机制为安全边界，具备较高的场景适配度和参赛展示价值。

## 四、项目目标

### 1. 总体目标

建设一个可演示、可扩展、可私有化部署的智慧教育学习运营平台，帮助学校和培训机构完成从“教学管理线上化”到“教学过程智能化”的升级。

### 2. 阶段目标

#### MVP 阶段

- 完成三角色工作台和基础业务闭环。
- 实现课程、作业、提交、评分、成绩、互评和通知功能。
- 接入课程资料索引和 RAG 问答。
- 实现学习计划 Agent 和 AI 批改建议 Agent。
- 提供可演示数据、接口文档和部署方案。

#### 试点阶段

- 在 1 至 3 门课程中进行真实或模拟教学试点。
- 收集教师批改建议采纳率、学生问答满意度、学习计划完成率等指标。
- 完善 AI 评测体系和安全边界。
- 优化教师端和学生端交互体验。

#### 推广阶段

- 支持更多课程类型和资料格式。
- 接入学校统一身份认证和教务数据。
- 支持多模型切换、本地模型部署和私有化交付。
- 形成可复制的 AI 教育平台解决方案。

## 五、产品方案

### 1. 角色设计

#### 管理员端

管理员端承担平台运营中枢角色，主要功能包括：

- 用户管理：新增管理员、教师、学生账号，启用或禁用用户。
- 课程管理：查看课程列表，调整教师归属、课程容量、分类、可见状态和学生选课。
- 活动管理：面向全部师生、教师或学生发布活动公告。
- 平台概览：查看学生人数、教师人数、课程数量、热门课程和运营优先级。
- 系统监控：观察平台基础运行状态和业务动态。

#### 教师端

教师端承担教学组织和教学反馈角色，主要功能包括：

- 创建和维护课程。
- 查看课程学生名单。
- 发布、编辑和删除作业。
- 上传作业附件，触发课程资料索引。
- 查看学生提交记录。
- 调用 AI 批改建议。
- 确认评分并写回成绩。
- 配置匿名互评规则。
- 查看作业成绩分析和班级学习情况。
- 使用智慧教育机器人进行课程教学辅助。

#### 学生端

学生端承担学习执行和反馈接收角色，主要功能包括：

- 浏览可选课程并完成选课。
- 查看已选课程和课程任务。
- 提交作业文本与附件。
- 查看成绩和教师评语。
- 完成匿名互评任务。
- 使用课程 RAG 助教提问。
- 获取学情诊断和个性化学习计划。

### 2. AI 功能设计

#### 课程 RAG 助教

平台将课程资料、作业说明和相关附件处理为文档切片，写入向量库。用户提问后，系统进行课程权限校验，检索相关片段，构造上下文，再调用大语言模型生成回答。回答结果保存问答日志，并返回引用来源、置信度和相关材料。

核心价值：

- 回答基于课程资料，减少泛化和幻觉。
- 不同角色拥有不同资料访问边界。
- 课程问答记录可沉淀为教学改进依据。

#### 学情诊断与学习计划 Agent

Agent 读取学生画像、课程成绩、作业提交和薄弱项，识别低分任务与待提升能力，结合课程资料生成阶段学习计划。

工作流：

```text
收集学生画像 -> 分析薄弱点 -> 检索课程资料 -> 规划每日任务 -> 生成练习 -> 校验计划 -> 保存学习报告
```

输出内容包括：

- 学习表现摘要。
- 薄弱作业和薄弱知识点。
- 一周学习计划。
- 每日学习任务。
- 推荐资料。
- 针对性练习。
- 后续改进建议。

#### 教师 AI 辅助批改 Agent

教师选择某个学生提交后，系统读取作业要求、提交内容、附件状态、评分标准和上下文，生成建议分数与评语。教师可采纳、修改或重新生成建议。最终成绩由教师确认后写入业务表。

核心原则：

- AI 提建议，教师做最终判断。
- 评分建议保留维度依据。
- 采纳与修改记录可用于后续评测和优化。

#### Agent 运行追踪

平台保存 AI 运行主记录、工具调用、问答日志、学习报告和批改建议。该能力用于：

- 展示 AI 执行过程。
- 排查异常和失败原因。
- 统计延迟、调用次数和结果质量。
- 为比赛答辩提供可解释性材料。

### 3. 核心业务闭环

#### 教师教学闭环

```text
创建课程 -> 发布作业 -> 上传资料 -> 学生提交 -> AI 辅助批改 -> 教师确认 -> 成绩分析 -> 教学改进
```

#### 学生学习闭环

```text
选课 -> 查看任务 -> 学习资料问答 -> 提交作业 -> 参与互评 -> 查看成绩 -> 获取学习计划 -> 针对性提升
```

#### 管理员运营闭环

```text
创建账号 -> 管理课程 -> 调整选课 -> 发布活动 -> 查看数据 -> 发现异常 -> 运营优化
```

## 六、技术方案

### 1. 技术选型

| 模块 | 技术 | 选择理由 |
| --- | --- | --- |
| 后端框架 | FastAPI | 异步性能好，API 文档自动生成，适合快速构建 AI 应用服务 |
| ORM | SQLAlchemy 2.0 Async | 支持异步数据库访问，结构清晰 |
| 数据库 | MySQL 8.0 | 稳定成熟，适合教育业务数据持久化 |
| 缓存与实时通信 | Redis、WebSocket | 支持通知、会话和实时推送扩展 |
| 前端 | HTML、CSS、JavaScript、Bootstrap、ECharts | 轻量直接，适合 MVP 演示和快速迭代 |
| 认证 | JWT | 前后端分离友好，适合多角色权限控制 |
| AI 编排 | LangChain Runnable、Agent 工具 | 支持可组合工作流和工具调用 |
| 向量库 | FAISS / Chroma | 适合课程资料语义检索 |
| 模型接入 | OpenAI、通义千问、Claude 等 | 便于多模型切换和不同部署环境适配 |
| 部署 | Docker、docker-compose、Nginx | 便于本地演示、服务器部署和反向代理 |

### 2. 系统架构

系统分为五层：

第一层是用户交互层，包括管理员、教师、学生三个静态前端工作台。

第二层是 API 服务层，由 FastAPI 提供认证、课程、作业、文件、通知、AI 等接口。

第三层是业务服务层，封装用户、课程、作业、选课、提交、评分、互评、通知等业务逻辑。

第四层是 AI 能力层，包括 LLM 封装、RAG 索引、向量检索、Agent Runtime、工具注册、学习计划链和批改建议链。

第五层是数据存储层，包括 MySQL 业务数据、AI 旁路表、文件存储、FAISS / Chroma 向量索引和 Redis。

### 3. 数据库设计

核心业务表：

- users：用户账号、角色、邮箱、状态。
- courses：课程信息、教师归属、容量、分类、可见状态。
- enrollments：学生选课记录、基础分、互评奖励和总分。
- assignments：作业信息、截止时间、满分、互评配置和附件。
- submissions：作业提交内容、附件、状态、成绩和教师评语。
- peer_reviews：匿名互评任务、评分、评语和奖励状态。
- notifications：通知标题、内容、类型、已读状态和接收人。
- published_activities：活动公告、受众、状态和发布时间。
- stored_files：上传文件元数据和业务绑定关系。
- audit_logs：重要操作审计记录。

AI 旁路表：

- ai_document_chunks：课程文档切片和向量索引元数据。
- ai_index_jobs：资料索引任务状态。
- ai_runs：Agent 运行主记录。
- ai_tool_calls：Agent 工具调用追踪。
- ai_agent_memories：Agent 记忆。
- ai_qa_logs：课程问答日志。
- ai_learning_reports：学情诊断与学习计划报告。
- ai_grading_suggestions：AI 批改建议和教师操作记录。
- ai_eval_results：离线评测结果。

### 4. 权限与安全设计

- 使用 JWT 识别当前用户身份。
- 根据 ADMIN、TEACHER、STUDENT 三类角色控制 API 访问。
- 教师只能访问自己课程下的学生、作业和提交。
- 学生只能访问自己选修课程、自己的提交和被分配的互评对象。
- 文件预览和下载前进行文件归属与课程权限校验。
- AI 问答检索时遵守课程和提交访问边界。
- 生产化阶段将补充更完善的审计、密钥管理、限流和内容安全策略。

## 七、项目创新性

### 1. 真实教学数据驱动的 AI

多数 AI 教育 Demo 停留在通用问答层面，EduAgent 将 AI 连接到真实业务表和教学流程，使 AI 输出基于课程、作业、提交、成绩和资料。

### 2. 多 Agent 工作流

项目不是单一 prompt 调用，而是将学习诊断、资料检索、任务规划、练习生成、批改建议等能力拆分为可追踪的工作流节点，具备进一步扩展多 Agent 协作的基础。

### 3. 教师审核优先

项目强调教师在教学评价中的主体地位，AI 只作为建议来源。这种设计更符合教育公平、责任边界和实际落地要求。

### 4. RAG 与权限控制结合

课程问答不仅检索资料，还考虑用户角色和资料可见范围，适合真实学校环境中对数据访问边界的要求。

### 5. 可解释与可评测

AI 的运行记录、工具调用、问答日志、评测结果都可持久化，后续可用于效果评估、答辩展示和模型迭代。

## 八、可行性分析

### 1. 技术可行性

项目已完成 FastAPI 后端、三角色静态前端、数据库模型、核心业务接口、AI 路由、RAG 基础、学习计划链、批改建议链和部署配置。所采用技术均为成熟开源组件，开发风险可控。

### 2. 场景可行性

高校课程、职业教育实训和培训课程都存在课程资料、作业、批改和学习反馈场景。项目功能与真实教学流程高度一致，便于进行课程级试点。

### 3. 运营可行性

MVP 可通过演示账号、模拟课程和样例数据完成完整展示。后续可从小规模课程开始试点，再逐步扩大到院系或机构级部署。

### 4. 经济可行性

项目基于开源技术栈构建，基础部署成本较低。AI 成本可通过模型选择、缓存、RAG 检索、调用限额和本地模型部署进行控制。

## 九、竞品分析

### 1. 超星学习通、智慧树、雨课堂

这些产品在高校教学平台中用户基础强，课程资源和教学活动功能成熟。但其核心能力仍偏课程管理、直播互动和资源分发，AI 个性化诊断、课程 RAG、批改建议和 Agent 运行追踪不是主要优势。

EduAgent 的机会在于以 AI Agent 为核心做轻量创新，适合作为院校 AI 教学改革试点和比赛原型。

### 2. Moodle、Canvas、Blackboard

这些平台具有成熟 LMS 能力和生态插件体系，适合大规模学校应用。但部署和定制门槛相对较高，AI 原生能力需要额外插件或二次开发。

EduAgent 的机会在于更轻量、更贴近 AI 教育应用展示，便于快速部署和迭代。

### 3. ChatGPT、豆包、通义千问等通用 AI 工具

通用 AI 工具自然语言能力强，但缺少课程级业务数据、权限控制、作业提交记录和教师确认流程。它们适合个体学习辅助，但难以直接承担学校级教学运营平台角色。

EduAgent 的机会在于把 AI 放进教育业务系统内部，让 AI 输出与课程、学生和教师流程绑定。

### 4. 作业帮、猿辅导等学习产品

这些产品在题库、拍题、讲解和 K12 学习场景中优势明显。但 EduAgent 面向高校、职业教育和机构课程运营，更强调课程过程管理、教师协作和平台级数据闭环。

## 十、市场与应用前景

### 1. 高校课程试点

平台可以先服务单门课程或课程组，用于课程资料答疑、作业批改建议、学生学习诊断和教学数据展示。

### 2. 职业教育实训

职业教育课程通常有大量项目作业和过程评价，EduAgent 的作业、互评、AI 批改和学习计划能力具有较强适配性。

### 3. 培训机构课程运营

培训机构重视学习效果和服务体验，平台可以帮助机构提供个性化学习计划和更及时的反馈。

### 4. 教育数字化成果展示

学校或团队可以基于 EduAgent 展示 AI+教育落地成果，包括系统架构、业务闭环、AI 运行轨迹和演示流程。

## 十一、实施计划

### 第一阶段：项目整理与参赛准备

时间：第 1 周

主要任务：

交付成果：

- 项目计划书。
- 演示数据脚本。
- 比赛展示路线。

### 第二阶段：MVP 功能稳定

时间：第 2 至 3 周

- 完善三角色核心页面体验。

交付成果：

- 稳定可演示版本。
- 核心功能检查清单。
- 端到端演示视频或截图。

### 第三阶段：AI 能力增强

时间：第 4 至 5 周

主要任务：

## 十七、风险分析与应对措施

### 1. AI 回答不准确

风险：大模型可能生成不准确、不完整或没有依据的回答。

应对：

- 使用课程 RAG 限定上下文。
- 输出引用来源。
- 对缺少资料支撑的问题进行拒答。
- 建立问答评测集和人工抽检机制。

### 2. AI 批改存在偏差

风险：AI 建议分可能与教师评价标准不一致。

应对：

- 教师确认后才写回正式成绩。
- 保留评分维度和依据。
- 记录教师采纳、修改和拒绝行为。
- 用教师评分数据持续评测和优化。

### 3. 数据隐私与权限风险

风险：学生作业、成绩和资料属于敏感教育数据。

应对：

- 角色权限控制。
- 课程范围访问控制。
- 文件访问校验。
- 后续增加审计、脱敏、加密和数据留存策略。

### 4. 部署与依赖复杂

风险：MySQL、Redis、向量库和 LLM 配置可能增加部署难度。

应对：

- 提供 Docker Compose 部署方案。
- 保留无 LLM 的降级体验。
- 提供环境变量模板和基线检查脚本。
- 优先保障比赛演示环境稳定。

### 5. 真实教学落地阻力

风险：教师可能担心 AI 增加额外操作或影响评分权威。

应对：

- 将 AI 放在辅助位置。
- 优化教师端操作路径。
- 强调批改建议可采纳、可修改、可拒绝。
- 用试点数据证明效率提升。

## 十八、商业模式与推广策略

### 1. 商业模式

- SaaS 订阅：面向培训机构和轻量课程试点。
- 私有化部署：面向高校、职校和大型机构。

- 形成开源版本 + 私有化版本 + 增值 AI 模块的组合路径。

## 十九、参赛展示方案

### 1. 展示主线

建议答辩展示围绕一句话展开：

“EduAgent 让 AI 不再停留在通用聊天，而是进入课程、作业、成绩和资料组成的真实教学闭环。”

### 2. 演示流程

第一步，管理员登录，展示用户、课程、活动和平台概览。

第二步，教师登录，创建课程或打开已有课程，发布作业，展示课程资料和作业任务。

第三步，学生登录，选课、查看作业、提交答案或附件，参与互评。

第四步，教师调用 AI 批改建议，展示建议分数、评语、优点、问题和教师确认机制。

第五步，学生调用学习计划，展示薄弱分析、一周任务和推荐练习。

第六步，展示课程 RAG 问答，强调回答来自课程资料并带引用。

第七步，展示 Agent 运行记录或日志，说明系统可解释、可追踪、可评测。

### 3. 答辩重点

- 痛点真实：教师减负、学生个性化学习、管理员数据运营。
- 技术完整：FastAPI、MySQL、RAG、LangChain、Agent、权限、日志。
- 创新明确：多 Agent 教学闭环、Human-in-the-loop 批改、课程级知识库。
- 落地可行：已有 MVP、可部署、可试点、可扩展。
- 风险可控：权限控制、引用来源、教师审核、评测机制。

## 二十一、结论

EduAgent 面向教育数字化中的真实痛点，结合课程管理、作业评价、学习诊断和大模型 Agent 技术，构建了一个可演示、可扩展、可参赛展示的智慧教育平台。项目既具备工程落地基础，又具备 AI 应用创新亮点；既服务教师减负，也服务学生个性化成长，并能为学校提供教学运营数据支持。

作为参赛项目，EduAgent 的优势在于场景明确、系统完整、技术路线可解释、原型可运行、后续商业化和试点空间清晰。后续通过评测指标、试点反馈和演示材料完善，有望形成具有代表性的 AI+教育应用案例。

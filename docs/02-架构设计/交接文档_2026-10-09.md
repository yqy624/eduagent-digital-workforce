### 2.4 阶段 A：YOLO 转常驻 HTTP 视觉服务 ✅

### 2.5 阶段 B：RAG 检索外置（对接 rag-go）✅

**做了什么**
- edu 的 `_search_course_chunks` **双路径分流**：`RAG_BACKEND=http-rag` 走外部服务，`local` 保留 FAISS/词法降级
- 上传附件**自动投递入库**（后台轮询至 `ready`，全程无人工干预）
- 权限**前置收窄**：先算可见 doc_id 白名单 → 传 `doc_ids`，不事后过滤
- 新增 `RagDocument` 映射表、`HttpRetrievalProvider`、统一 `http_client.py`（`trust_env=False` 绕代理）

**为什么 / 关键取舍**
- 边界：**rag-go 管"知识和证据"，edu 管"谁的、能看吗"**
- 入库走 **multipart 不走 from-object**：edu 无 MinIO 写入实现、bucket 不一致，multipart 反而省事且**支持自定义 doc_id**
- **score 不做阈值过滤**：实测 hybrid 返回 RRF 融合分（0.4~0.5）与 vector cosine（0.0167）**不是一个量级**，只信任外部排序

**证据（全绿）**
1. 上传 → 自动投递 → `ready`，无人工干预
2. 学生提问命中 `ragDocId`，answer 正常
3. **权限隔离正确**：student01 见自己附件，02/03 不可见，教师/管理员全可见
4. **降级正确**：kill rag-go 后提问**返回 200 而非 500**
5. 4 个调用点零回归
6. **质量对比铁证**：同一问题 local 返回 3 条全是词法打平的"提交：冒烟作业…"（**漏掉课程资料**），http-rag 精确命中真实段落 → 坐实"edu 名义 RAG 实为关键词匹配"

### 2.6 阶段 C：视觉感知链路修复（上传即感知 + 事件派生）✅

**派生层的三条自我约束（答辩核心，必须守住）**
1. **只做阳性派生，不做阴性判断** —— 通用权重没有 goggles/gloves 类别，拿它的沉默报"未佩戴"= 把模型短板说成学生违规

3. **事件必须可追溯** —— evidence 带 `cls_name/conf/bbox`，人能回原图核对

**两种执行节奏（不是一刀切）**
- **需人工复核**（`paper_grading`）：只登记 `pending`，教师在工作台触发（批改影响分数，不能让模型跑完就落分）

**证据（全绿）**

### 2.7 运维：一键启动脚本 + 加固 ✅

**做了什么**
- `scripts/start_all.ps1`（UTF-8 带 BOM，PS 5.1 兼容）：按依赖顺序拉起 6 个服务，启动期 + 运行期**持续输出**（服务名/地址/端口/PID/实时日志/每 15s 心跳）
- 参数：`-Stop` / `-StopAll` / `-Restart` / `-Only "yolo,edu"` / `-NoTail` / `-ReadyTimeout`

**加固的 6 项（把"服务已在跑"从撒手不管变成能识别/接管/管住）**
1. **PID 以端口反查为准**（不再信 `Start-Process` 的 shim PID）
2. **pids.json 改 v2 合并语义**（`{pid,shimPid,owned,port,startedAt}`，再不会被覆盖成 `{}`）
3. **复用也进心跳循环**（修掉"全是复用就直接退出"）
4. **身份校验**（务必命中关键词才复用，否则报"端口冲突"）
5. **停止分三级**（Ctrl+C / `-Stop` / `-StopAll`）+ `-Restart`
6. **接管继承 shimPid/startedAt**

**证据**：6 个场景逐项实测通过（A 复用接管 / B StopAll / C 冷启动 / D 双实例 / E shimPid 继承 / F 端口冲突）。

**写脚本踩到的坑（都是环境级教训，别人复现必踩）**
1. **环境变量大小写重复**：本机同时有 `http_proxy` + `HTTP_PROXY` 等 4 条仅大小写不同的变量 → `Start-Process` 抛「字典中的关键字」
2. `-ArgumentList` 收空数组被判 null → 改 splatting
3. `cmd.exe` 走 `Test-Path` 判不存在 → ES 被整段跳过
4. PS 5.1 的 `*>` / `Out-File` 默认写 UTF-16 → 日志乱码

## 5. 后续推进优先级（**核心建议**）

> 判断依据：毕设主题是「YOLO + Agent 多场景智能教育视觉感知与反馈系统」，**答辩要论证的是"视觉是源、教育业务是消费方"**。当前最大的短板不是功能不够，而是**这条主线还没真正连起来**。

### 第一优先：修 identity 连接键（让主线"成立"）✅ 已完成（2026-10-10）

> 已按**方案 A** 落地：`users` 新增 `student_no` 列，连接键改为 `vision_identities.student_no == users.student_no`。
> 修复前 join 命中 0 条、`engagement` 恒空；修复后命中 7 条，`student01` 参与度返回 4 条事件。
> 完整改动与验证见 `身份连接键修复_2026-10-10.md`。

**为什么排第一**：这是**最低成本、最高收益**的动作。不修它，`insight/engagement` 和 `insight/reports` 永远返回空 —— 导师一眼就能看出"视觉核心"只是菜单主张。

**怎么做（两个方向，建议选 A）**
- **方案 A（改对齐口径）**：统一标识 —— 要么 `vision_identities.student_no` 改存 `student01`，要么把 `users` 补一个 `student_no` 列与学号对齐；然后在 `insight/engagement`、`insight/reports` 的 join 处显式绑定

**验收标准**：`insight/engagement` 从"永远空"变成"有数"，学生画像里能看到视觉事件归属到具体学生。

### 第二优先：扩大视觉消费面（让主线"有说服力"）

**为什么**：修完 #1 后消费面仍只有 4 个能力。要让"视觉为核心"站得住，至少再补几条**真实的消费链路**，例如：

**注意**：这属于"锦上添花"，**必须先有 #1**（没有身份归属，消费出来的还是空数据）。

## 6. 运维手册

### 6.1 一键启动（推荐）

```powershell
cd ~\Desktop\edu-ai-platform
powershell -ExecutionPolicy Bypass -File .\scripts\start_all.ps1
```

启动顺序：Milvus（只检测）→ MinIO → ES → rag-go → yolo-platform → edu。

> **Milvus 是 Docker 容器，脚本只检测不代管**。没跑时先 `docker compose up -d`（那是 rag-go 侧的 compose，见 rag-go 仓库）。

### 6.2 停止

| 操作 | 停止范围 |
|---|---|
| `Ctrl+C` | 只停**本次脚本自启**的服务 |
| `-Stop` | 停**由脚本启动过**的服务（含上一轮、被接管的） |
| `-StopAll` | 停 pids.json 记录的**全部**（含外部复用实例） |

> ⚠️ **别用"强杀进程"来停脚本** —— 强杀会连带回收 `Start-Process` 派生的子进程（服务一起死）；手动 `Ctrl+C` 不会。停服务请用 `-Stop` / `-StopAll`。

### 6.3 手动启动（调试单个服务时用）

```bash
# edu 主服务（全功能）
cd ~/Desktop/edu-ai-platform
DB_BACKEND=sqlite MODEL_VISION_BACKEND=http-yolo VISION_SERVICE_URL=http://127.0.0.1:8000 \
RAG_BACKEND=http-rag RAG_SERVICE_URL=http://127.0.0.1:9004 \
.venv/Scripts/python.exe run.py --host 127.0.0.1 --port 8001
```

> edu / yolo / rag-go **均无 `--reload`**，改后端代码必须重启。

### 6.4 验证服务是否真的在跑

```bash
curl -s --noproxy '*' http://127.0.0.1:8001/api/health | head -c 400   # vision.effective 应为 http-yolo
curl -s --noproxy '*' http://127.0.0.1:9004/api/v1/health              # 看 ok / es_ok / milvus_ok / rag_ready
curl -s --noproxy '*' http://127.0.0.1:8000/health
curl -s --noproxy '*' http://127.0.0.1:9200/_cluster/health            # status green
```

### 6.5 常见坑速查

| 现象 | 原因 / 处理 |
|---|---|
| 本地 curl 报 502 / 连不上 | 本机有 `http_proxy`，**必须加 `--noproxy '*'`**（代码侧用 `app/core/http_client.py`） |
| ES 启动失败 | JDK17 上必须加 `-E xpack.ml.enabled=false -E xpack.security.enabled=false` |
| rag-go 入库 failed 但 health `ok=true` | **ES 没起**（入库强依赖 ES，health 不反映） |
| 新上传的文档检索不到 | edu `RagDocument` 状态曾卡 `pending` —— 检索已放宽（只排除 failed），后台会轮询收敛 |
| `Start-Process` 抛「字典中的关键字」 | 环境变量大小写重复（`http_proxy`+`HTTP_PROXY`）；脚本已自清理 |
| 登录 401 | 请求体没带 `role`，或没跑 `seed_demo.py` |
| 读返回字段取不到 | 中间件只把**响应**转 camelCase，**请求体必须 snake_case** |

## 8. 关键决策记录（为什么这么设计）

| 决策 | 理由 |
|---|---|
| **视觉拆 HTTP，RAG 只拆检索不拆索引** | 视觉调用点唯一、契约已就位，成本极低；RAG 索引涉及 chunk 权限绑定，写路径风险高，最后做 |
| **RAG 入库走 multipart 不走 from-object** | edu 无 MinIO 写入实现、bucket 不一致；multipart 支持自定义 doc_id |
| **RAG score 不做阈值过滤** | hybrid 是 RRF 融合分，与 cosine 不同量级，只信任外部排序 |
| **权限前置收窄而非事后过滤** | 后置会导致召回数量缩水 + 越权内容已在网络流转 |
| **检索放行 pending/processing** | edu 状态是快照可能滞后，只认 ready 会导致新文件整段时间检索不到 |
| **派生层只做阳性派生** | 通用权重没有安全装备类别，阴性判断 = 把模型短板说成学生违规 |
| **批改场景需人工复核** | 批改影响分数，不能让模型跑完就落分 |
| **Milvus 只检测不代管** | 它是 Docker，`taskkill` 会误杀 WSL 转发进程 |
| **课程/作业/成绩不拆服务** | 强事务，拆了没有收益 |

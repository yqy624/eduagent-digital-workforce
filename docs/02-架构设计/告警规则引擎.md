# 告警规则引擎 · 2026-10-10

> **主题**：让视觉事件产生**业务动作**，而不是只等页面来读
> **对应交接文档**：§4 P0 #2「视觉消费面仅 8%」/ §5 第二优先「扩大视觉消费面」
> **状态**：✅ 已完成并端到端验证

---

## 1. 为什么做这一环

2026-10-09 的架构评估给出一条硬数据：**49 项能力里只有 4 项真正消费视觉事件（8%）**。
而 2026-10-10 上午修好身份连接键后，消费侧仍有一个更本质的缺口：

> **视觉事件只被"展示"，没有被"消费"。**

在规则引擎之前，一条 `no_gloves / critical` 的归宿是：静静躺在 `vision_events` 表里，
等某个页面把它读出来渲染成一行字。**没有人被通知，没有任何业务状态被改变。**
`situation/rules` 端点也如实返回 `implemented: false`，并承认：
"当前确认动作已可用并写回事件。缺的是「按等级自动路由到责任人」的规则与派发端点。"

**消费方的动作应该是"通知"，而不是"展示"。** 这就是本次补上的一环。

## 2. 设计

```
视觉事件落库（vision_events）
        │
        ▼
   AlertRuleService.evaluate()        ← 新增：同一事务内执行
        │
        ├─ 1. 等级过滤：event.severity ≥ rule.severity（info 不告警）
        ├─ 2. 场景匹配：rule.scene 为空表示不限场景
        ├─ 3. 路由到人：
        │      · notify_student → 由 subject_ref（业务学号）反查学生账号
        │      · notify_roles   → 按角色取 教师 / 管理员
        ├─ 4. 去重：同标题在 dedup_minutes 窗口内只发一次
        ▼
   notifications 表 + WebSocket 实时推送（复用 NotificationService）
```

**三条自我约束**（与事件派生层同一态度）：

1. **只消费已有事实** —— 不猜测、不补全事件内容，只做匹配与路由
2. **不打扰** —— 持续违规会不断产生事件，同标题在窗口内只发一次
3. **可解释** —— 通知正文带等级、置信度、任务号与命中的规则名，人能回溯原图与任务

**降级边界**：派发失败只记日志，**不影响"事件已落库"这一事实**（try/except 包裹）。

## 4. 验证证据（全部实测）

**默认规则**（种子）：

| # | 名称 | 场景 | 触发等级 | 通知学生 | 通知角色 | 去重 |
|---|---|---|---|---|---|---|
| 1 | 实验室严重违规即时告警 | lab_safety | ≥ critical | 是 | TEACHER,ADMIN | 10 min |
| 2 | 课堂行为关注项上报 | classroom | ≥ warning | 否 | TEACHER,ADMIN | 30 min |
| 3 | 考场异常全局告警 | exam_proctor | ≥ warning | 是 | ADMIN | 5 min |

**闭环实测**：以管理员跑一次 `lab_safety` 视觉任务 →

```
任务 VT2026101011041471579F  status = succeeded
事件  no_goggles / critical / subject S2024002 / seat BENCH-02
事件  no_gloves  / critical / subject S2024001 / seat BENCH-01

→ student01 收到 1 条「[视觉告警] 实验室安全识别：未佩戴手套（S2024001）」
→ teacher01 收到 2 条（两条事件各一条）
```

> 事件归属正确：`student01` 只收到属于自己的那条，**没有收到 `S2024002` 的**。

**边界用例**：

| 用例 | 结果 |
|---|---|
| 去重：同场景再跑一次 | `student01` 告警数 **1 → 1**（未重复打扰） |
| `GET /rules` | `implemented = true`，3 条规则字段完整 |
| `POST /rules` 管理员 | HTTP 200 |
| `POST /rules` 学生 | **HTTP 403**（仅管理员可配置） |
| 非法场景 `not_a_scene` | **HTTP 422**（入参校验拦截） |
| `PUT /rules/{id}/enabled` | HTTP 200，`enabled` 正确翻转 |
| 整体回归 | `/api/health` 200；路由数 **154 → 156**（新增 2 个端点） |

## 5. 对毕设主线的意义

修复前，答辩演示只能停在"事件列表里有几条红色记录"。
现在可以演示**完整的消费闭环**：

```
上传实验室照片 → YOLO 推理 → 事件落库 → 按学号归属到学生
     → 规则引擎命中 → 学生/教师的工作台立刻收到一条待办
```

这是"**视觉是源、业务是消费方**"最直接的证据：
视觉产生的不再是数据，而是**被派发出去的业务动作**。

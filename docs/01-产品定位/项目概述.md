# EduAgent 项目概述

## 一、项目名称

EduAgent — 基于多 Agent 的智慧教育学习运营平台

## 二、项目一句话简介

EduAgent 是一个面向高校、职业院校和培训机构的 AI 教育平台，将课程、作业、成绩、资料、互评和 AI Agent 放在同一个教学运营流程中，帮助管理员看清平台运行状态，帮助教师提升教学与批改效率，帮助学生获得基于课程资料和个人学习数据的个性化学习支持。

## 三、产品描述

EduAgent 的核心定位不是单纯的教务系统，也不是单独的 AI 聊天工具，而是一个围绕“教学全过程数据”构建的智慧教育工作台。平台以管理员、教师、学生三类角色为主线，覆盖课程管理、选课管理、作业发布、作业提交、教师批改、匿名互评、成绩分析、活动通知、课程资料索引、RAG 问答、学情诊断、学习计划生成、AI 批改建议和 Agent 运行追踪等功能。

当前项目已经具备 Preview / MVP 形态，可用于课程设计、开源展示、创新创业比赛、人工智能应用比赛和教育数字化原型验证。它的重点价值在于：把传统教育管理系统中分散的“课程、作业、成绩、资料、互动记录”转化为 AI 可以理解、检索、推理和辅助决策的数据基础。

## 四、产品背景

### 1. 教育数字化进入深水区

近年来，高校和培训机构普遍完成了线上教学平台、教务管理平台和资源平台的基础建设，但这些系统仍以“记录”和“流转”为主，智能化程度有限。课程资料、作业结果、成绩数据和师生反馈往往分散存储，无法自然形成学生画像、学习诊断和教学改进建议。

### 2. 大模型给教育平台带来新机会

大语言模型具备自然语言理解、生成、总结和推理能力，但通用聊天工具直接进入教学场景仍存在几个问题：不了解课程上下文、不能连接真实作业和成绩、回答缺少来源、难以与教师审核流程结合、不能形成可追踪的教学闭环。

EduAgent 通过 RAG、Agent 工具调用、学习画像和 Human-in-the-loop 批改机制，将大模型能力接入真实教学业务流程，降低“AI 幻觉”和“脱离课堂”的风险。

### 3. 教师与学生都需要更具体的智能支持

教师端需要解决作业批改耗时、学情掌握滞后、教学反馈碎片化、资料答疑重复劳动等问题；学生端需要解决学习路径不清晰、薄弱点难定位、资料检索效率低、作业反馈不及时等问题。EduAgent 将这些问题归入同一套数据与 AI 工作流中处理。

## 五、目标用户群体

### 1. 核心用户

#### 高校教师

高校教师是平台最直接的高频用户。他们需要创建课程、发布作业、管理学生、查看提交记录、配置匿名互评、批改作业、查看成绩分布，并借助 AI 生成批改建议、讲评思路和学习诊断。

教师的核心诉求包括：

- 减少重复性答疑和低价值批改时间。
- 快速了解班级整体学习状态。
- 基于真实作业和成绩发现共性问题。
- 保留最终评分权，避免 AI 完全替代人工判断。

#### 学生

学生是平台学习侧价值的主要受益者。学生可以选课、查看课程任务、提交作业、参与匿名互评、查看成绩与反馈，并通过 AI 助教进行课程资料问答、获得个人学习计划和针对性练习建议。

学生的核心诉求包括：

- 快速找到课程资料中的关键内容。
- 得到更及时、更具体的作业反馈。
- 知道自己薄弱在哪里、下一步该学什么。
- 在互评过程中学习同伴的思路和表达方式。

#### 教学管理员

教学管理员负责平台级运营与管理，包括用户管理、课程管理、活动发布、选课调整、课程上下架、平台监控、统计分析和运营优先级判断。

管理员的核心诉求包括：

- 快速掌握平台用户、课程和任务运行情况。
- 统一管理师生账号和课程容量。
- 及时发布活动与通知。
- 发现课程运营异常和任务积压。

### 2. 扩展用户

#### 教务部门与院系管理者

教务部门可以使用平台汇总课程参与、作业完成、成绩分布和教学反馈数据，为教学质量评估、课程建设和教师支持提供依据。

#### 职业教育与培训机构

职业教育和培训机构通常强调学习结果、任务完成率和个性化提升路径。EduAgent 可用于项目制课程、实训作业、阶段测评和学习陪跑。

#### 教育技术研究团队

研究团队可以基于平台的 Agent 运行轨迹、RAG 问答日志、批改建议采纳记录和学习计划结果，开展 AI 教育应用、学习分析和人机协同教学研究。

## 六、核心功能

### 1. 三角色协同工作台

平台提供统一登录入口，根据用户角色进入管理员、教师或学生工作台。

- 管理员端：用户管理、课程管理、选课调整、活动发布、系统监控、数据概览。
- 教师端：课程管理、学生名单、作业发布、提交查看、评分、互评配置、成绩分析、AI 助教。
- 学生端：课程浏览、选课退课、作业查看、作业提交、互评任务、成绩查看、AI 学习计划。

### 2. 课程与作业管理

教师可以创建课程、设置课程描述、时间、容量、学分等信息，并为课程发布作业。作业支持标题、说明、详情、截止时间、满分和附件。学生选课后可以查看对应课程作业并提交文本或附件。

### 3. 文件与课程知识库

平台支持作业附件、学生提交附件和课程资料的上传、预览、下载与权限控制。AI 模块可对课程相关资料进行加载、切片、向量索引，形成课程级知识库，为 RAG 问答和学习计划提供材料基础。

### 4. 课程 RAG 助教

学生或教师提问时，系统会优先检索课程资料、作业附件和可访问的学习材料，再基于检索结果生成回答。回答设计上强调引用来源和权限边界，避免把无资料支撑的内容伪装成课程事实。

### 5. 学情诊断与学习路径规划

学习计划 Agent 会读取学生课程、作业、提交、成绩和薄弱项数据，生成阶段性学习诊断、一周学习任务、推荐练习和资料建议。工作流包含画像收集、薄弱分析、资料检索、任务规划、练习生成、计划校验和报告保存。

### 6. 教师 AI 辅助批改

教师可以针对学生提交调用 AI 批改建议。系统结合题目要求、作业详情、学生答案、附件状态、互评信息和评分标准，生成建议分数、评语、优点、问题和评分维度。最终成绩仍由教师确认后写回，形成 Human-in-the-loop 闭环。

### 7. 匿名互评

教师可以为作业开启匿名互评，配置开放时间、截止时间、互评数量、奖励分值、奖励上限和互评提示语。学生完成互评后，系统可记录互评状态并计算互评奖励，帮助学生在评价他人作品的过程中提升反思能力。

### 8. 通知与活动发布

平台提供通知中心和 WebSocket 实时推送能力。作业发布、互评开启、成绩完成、活动公告等事件可以触达相关师生，减少教学过程中的信息滞后。

### 9. AI 运行追踪与评测基础

系统内置 AI Run、Tool Call、QA Log、Learning Report、Grading Suggestion、Eval Result 等旁路数据表，用于记录 Agent 执行状态、工具调用轨迹、问答日志、学习报告和批改建议。该设计便于后续做可解释性分析、质量评估和比赛展示。

## 七、产品价值

### 1. 对学生的价值

- 将“我不会什么”转化为可执行的学习计划。
- 将课程资料问答从通用搜索变成基于课程上下文的答疑。
- 通过即时反馈和互评提升学习主动性。
- 用可视化成绩和任务状态减少学习盲区。

### 2. 对教师的价值

- 降低批改和重复答疑压力。
- 帮助教师快速发现班级共性薄弱点。
- 保持教师对评分、反馈和教学决策的最终控制权。
- 把课程资料、作业表现和反馈数据沉淀为可复用教学资产。

### 3. 对学校与机构的价值

- 提升教学过程数据化和智能化水平。
- 支持课程质量监控、学习预警和教学改进。
- 为教育数字化建设提供可落地的 AI 应用样板。
- 降低引入智能教育能力的试点成本。

## 八、项目愿景

EduAgent 的长期愿景是成为“以学习者成长为中心的 AI 教育协同平台”。平台希望实现三个层面的进化：

第一，从管理系统进化为学习运营系统。传统系统只记录课程、作业和成绩，EduAgent 希望进一步理解学习过程，帮助师生发现问题并采取行动。

第二，从单点 AI 功能进化为多 Agent 教学协作网络。不同 Agent 分别承担课程资料答疑、学情诊断、作业批改、教学建议、预警分析等任务，并通过工具调用和业务数据协作。

第三，从结果评价进化为过程支持。平台不仅关注最终成绩，更关注学习行为、任务完成、反馈质量和持续改进，让 AI 成为学生学习路径上的陪跑者，也成为教师教学改进中的助理。

## 九、技术架构

### 1. 总体架构

EduAgent 采用前后端相对轻量的 MVP 架构：

- 前端：静态 HTML、CSS、JavaScript、Bootstrap、ECharts。
- 后端：Python FastAPI。
- 数据访问：SQLAlchemy 2.0 Async。
- 数据库：MySQL 8.0。
- 缓存与实时能力：Redis、WebSocket 通知。
- 认证：JWT 无状态认证。
- AI 编排：LangChain Runnable、Agent 工具注册与运行追踪。
- RAG：文档加载、文本切片、向量索引、FAISS / Chroma 向量库。
- LLM：可配置 OpenAI、通义千问、Claude 等模型提供方。
- 部署：Dockerfile、docker-compose、Nginx 配置。

### 2. 数据架构

平台业务数据包括用户、课程、选课、作业、提交、互评、通知、活动、文件和审计日志。AI 旁路数据包括文档切片、索引任务、Agent 运行记录、工具调用、Agent 记忆、问答日志、学习报告、批改建议和评测结果。

这种“业务主表 + AI 旁路表”的设计既保持原有教育业务模型稳定，又便于独立扩展 AI 能力和评测能力。

### 3. AI 工作流

学习路径规划 Agent：

```text
收集学生画像 -> 分析薄弱点 -> 检索课程资料 -> 规划学习任务 -> 生成练习 -> 校验计划 -> 保存报告
```

教师批改 Agent：

```text
读取提交 -> 获取作业要求 -> 生成评分建议 -> 教师确认 -> 写回成绩 -> 沉淀反馈记录
```

课程 RAG 问答：

```text
问题输入 -> 权限校验 -> 课程资料检索 -> 构造上下文 -> LLM 回答 -> 引用来源记录 -> 问答日志保存
```

## 十、创新点

### 1. 教学业务闭环中的 AI Agent

EduAgent 不是把聊天机器人简单嵌入页面，而是让 Agent 通过工具读取课程、作业、成绩、提交、资料和通知等真实业务数据，生成与教学过程相关的建议。

### 2. Human-in-the-loop 批改机制

AI 不直接替代教师评分，而是提供建议分数、评语和评分维度。教师确认、修改或拒绝后再写回成绩，兼顾效率、责任边界和教育公平。

### 3. 课程级 RAG 知识库

平台把课程资料、作业说明和相关附件纳入课程知识库，使 AI 问答能够回到具体课程上下文，而不是依赖通用知识泛泛回答。

### 4. 学情诊断与任务规划结合

系统不仅输出“薄弱点分析”，还进一步生成一周学习计划和练习任务，把诊断结果转化为可执行行动。

### 5. 可追踪、可评测的 AI 运行体系

AI 运行过程被记录为 Run、Tool Call、QA Log 和 Eval Result，为比赛答辩中的可解释性、安全性和效果评估提供基础。

## 十一、竞争对手与竞品分析

### 1. 传统在线教学平台

代表产品包括超星学习通、智慧树、雨课堂、Moodle、Canvas、Blackboard 等。

优势：

- 教学资源、课程管理和作业管理功能成熟。
- 有较强的学校部署基础和用户习惯。
- 支持大规模课程组织和教学管理。

不足：

- 多数平台仍偏流程管理和资源分发，AI 个性化学习支持不足。
- 学情分析往往停留在统计层面，缺少可执行学习计划。
- 批改辅助、课程资料问答和 Agent 协同能力相对薄弱。

EduAgent 的差异点：

- 以 AI Agent 为核心增强教学流程。
- 强调课程资料 RAG、学情诊断、学习计划和 AI 批改闭环。
- 更适合展示新一代 AI 教育平台的原型能力。

### 2. 通用协作与班级管理工具

代表产品包括钉钉、企业微信、腾讯会议、飞书等。

优势：

- 通知、沟通和组织协作能力强。
- 用户覆盖广，移动端体验成熟。
- 适合班级群、直播课和日常沟通。

不足：

- 教学数据结构化程度有限。
- 对作业、成绩、课程知识库和学习诊断支持不足。
- AI 功能通常偏通用办公场景，缺少教育业务闭环。

EduAgent 的差异点：

- 以课程、作业、提交、成绩为核心数据模型。
- 将教学通知与学习任务、互评、批改、诊断连接。
- 可作为教育业务系统，而不只是沟通工具。

### 3. AI 学习助手与答疑产品

代表产品包括 Khanmigo、作业帮、猿辅导、豆包学习助手、通义千问教育应用、ChatGPT 等。

优势：

- AI 对话和知识解释能力强。
- 适合个体学生自学、题目讲解和快速答疑。
- 部分产品拥有丰富题库和内容生态。

不足：

- 与学校真实课程、作业、成绩和教师反馈连接较弱。
- 难以形成学校级教学运营数据闭环。
- 通用 AI 工具存在来源不明、上下文不足和责任边界模糊的问题。

EduAgent 的差异点：

- 从课程平台内部生长 AI 能力，而不是外接一个通用问答入口。
- AI 回答与课程资料、作业和学生画像绑定。
- 教师参与评分确认，降低 AI 决策风险。

### 4. 教育数据分析平台

代表产品包括各类学习分析系统、教务质量监控平台和数据大屏。

优势：

- 统计分析、报表展示和管理视角较强。
- 适合教学质量评估和学校管理。

不足：

- 多数系统偏事后分析，缺少面向学生和教师的即时行动建议。
- 对自然语言问答、作业反馈和个性化学习路径支持有限。

EduAgent 的差异点：

- 不只展示数据，还把数据转化为学习计划和教学建议。
- 同时服务管理员、教师和学生，而不是单一管理视角。

## 十二、市场机会

### 1. 高校 AI+教育应用试点需求增加

高校正在积极探索人工智能赋能教学、课程建设和学生发展。EduAgent 可以作为小规模课程试点平台，快速验证 AI 助教、智能批改和学习诊断的可行性。

### 2. 教师减负与个性化学习需求明确

作业批改、资料答疑和学习反馈是高频痛点。平台若能在保障教师主导权的前提下提升效率，具备较强应用价值。

### 3. 开源和私有化部署空间

学校和机构对数据安全、学生隐私和模型可控性要求较高。EduAgent 基于 FastAPI、MySQL、FAISS / Chroma 等组件，具备私有化部署和二次开发潜力。

## 十三、商业模式设想

### 1. SaaS 订阅

面向中小培训机构和轻量试点课程，提供按教师数、学生数或课程数计费的云端服务。

### 2. 私有化部署

面向高校、职校和大型培训机构，提供私有化部署、模型接入、数据迁移和定制开发服务。

### 3. AI 能力增值包

基础教务功能免费或低价，课程知识库、AI 批改、学习诊断、教学分析、评测报表等作为增值模块。

### 4. 教育数据分析服务

在合规前提下，为学校提供课程质量分析、学习风险预警、教学改进建议和年度报告服务。

## 十四、当前项目基础

项目已具备以下基础：

- FastAPI 后端服务与 Swagger API 文档。
- 管理员、教师、学生三角色页面。
- 用户、课程、选课、作业、提交、成绩、互评、通知等核心表结构。
- JWT 登录、注册、找回密码和个人主页。
- 文件上传、预览、下载和权限校验。
- 课程 RAG 问答接口和资料索引接口。
- 学习计划 Agent 工作流。
- 教师 AI 批改建议工作流。
- Agent 运行记录、工具调用记录和 AI 评测结果表。
- Docker、Nginx 和部署配置基础。

## 十五、当前限制与迭代方向

当前版本仍属于 Preview / MVP，后续需要重点补齐：

- 更完善的生产级权限审计和数据隔离。
- 更完整的文件安全扫描和内容审核。
- AI 评测基线、准确率评估和教师采纳率分析。
- 更丰富的课程资料解析能力。
- 更完整的移动端体验。
- 大规模并发下的性能优化和任务队列。
- 面向真实教学试点的用户研究和反馈闭环。

## 十六、总结

EduAgent 以“多 Agent + 教学全过程数据”为核心，将教育管理、学习支持和 AI 生成能力结合起来。它既保留传统教学平台的课程、作业、成绩等基础能力，又通过 RAG 问答、学习计划、AI 批改建议和运行追踪形成智能化升级路径。

作为参赛项目，EduAgent 具备明确的教育场景、可演示的 MVP、较完整的技术架构和可持续迭代空间，适合定位为“AI 赋能教育数字化”的应用型创新项目。
